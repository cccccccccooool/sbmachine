# AI 文档维护规则

本文档用于指导 AI 创建和维护项目工程文档。

当项目缺少必要说明，或代码修改导致现有文档过时时，请根据实际需要创建或更新对应文档，例如：

* `architecture.md`：系统架构、模块边界和主要数据流；
* `modules/<name>.md`：模块职责、入口、接口、依赖和约束；
* `testing.md`：测试结构、运行命令和验收方法；
* `operations.md`：安装、配置、部署和故障处理；
* `decisions/<id>.md`：重要设计选择及其原因。

维护时遵守以下原则：

1. 只记录已经由代码、配置或测试确认的事实，不将猜测或未实现方案写成现状。
2. 只读取和更新与当前任务相关的文档，不默认扫描或重写全部文档。
3. 优先修改已有文档，避免创建内容重复的新文件。
4. 文档应说明职责、边界、接口、约束和验证方法，不逐行复述源码。
5. 内部实现变化但外部行为和模块契约未改变时，不必更新文档。
6. 若本次修改改变了架构、接口、配置、运行方式、测试方法或长期设计决策，必须同步更新对应文档。
7. 无法确定代码与文档哪一方正确时，应明确报告冲突，不得自行编造解释。
8. 完成后列出已创建或更新的文档；若无需更新，说明原因。
